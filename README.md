# Servico — Services Management System

Servico is a web application that connects **customers** who need home/professional services with **service companies** that provide them, under the supervision of an **admin** who approves which companies are allowed on the platform.

It is a Spring Boot 3 application: a REST API written in Java 17 with JPA persistence, serving a plain HTML/CSS/JavaScript front end from `src/main/resources/static`.

---

## What it does

**Customers**
- Sign up and log in
- Browse services published by approved companies
- Book a service (date, time, service type/tier, location, contact details)
- Track a booking's status: `PENDING` → `ACCEPTED` / `REJECTED` / `COMPLETED`
- Leave a star rating and written review after a booking

**Companies**
- Register a company account (name, services offered, contact, address)
- Wait for admin approval before the account becomes usable
- Log in and manage a company dashboard
- Publish services with three price tiers (average / premium / VIP) and opening hours
- See incoming bookings and accept, reject, or complete them
- View the reviews customers left for them

**Admin**
- Log in at the Servico admin dashboard
- List all registered companies
- Approve or reject company registrations
- A default admin (`admin` / `admin123`) is created on first startup by `DataInitializer`

Email notifications are sent through Spring Mail (`MailConfig`) when mail credentials are configured.

## How to run

### 1. Quick start (H2 in-memory database — nothing else to install)

Windows (PowerShell / CMD):

```bat
.\mvnw.cmd spring-boot:run
```

macOS / Linux:

```bash
./mvnw spring-boot:run
```

Then open <http://localhost:8080>.

The database is created in memory at startup and **discarded when the app stops**, so every restart begins with empty data plus the default admin. The H2 web console is available at <http://localhost:8080/h2-console> with JDBC URL `jdbc:h2:mem:servico`, user `sa`, empty password.

### 2. Running with MySQL (data survives restarts)

Make sure MySQL is running locally, then:

```bash
# macOS / Linux
DB_USERNAME=root DB_PASSWORD=yourpassword ./mvnw spring-boot:run -Dspring-boot.run.profiles=mysql
```

```powershell
# Windows PowerShell
$env:DB_USERNAME="root"; $env:DB_PASSWORD="yourpassword"
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=mysql"
```

The `servico` schema is created automatically (`createDatabaseIfNotExist=true`) and tables are generated by Hibernate (`ddl-auto=update`). Connection settings live in `src/main/resources/application-mysql.properties`.

### 3. Enabling email notifications (optional)

Credentials are read from environment variables and are never committed:

```powershell
$env:MAIL_USERNAME="your.address@gmail.com"
$env:MAIL_PASSWORD="your-app-password"   # a Gmail App Password, not your login password
```

Leave them unset to run the app without mail delivery.

### 4. Build a runnable JAR

```bash
./mvnw clean package
java -jar target/FinalYearProject-0.0.1-SNAPSHOT.jar
```

### 5. Run the tests

```bash
./mvnw test
```

## Using the app

1. Go to <http://localhost:8080> — the landing page offers User, Company, and Servico (admin) entry points.
2. **Register a company** at `companysignup.html`. It starts with status `Pending`.
3. **Log in as admin** at `servicologin.html` with `admin` / `admin123` and approve the company from the Servico dashboard.
4. **Log in as the company** at `companylogin.html` and add services from the company dashboard.
5. **Sign up as a customer** at `usersignup.html`, browse services, and place a booking.
6. The company accepts/completes the booking; the customer then rates and reviews it.

## REST API

All endpoints are under `/api`. Base URL: `http://localhost:8080`.

**Users** — `/api/users`
| Method | Path | Purpose |
|---|---|---|
| POST | `/signup` | Register a customer |
| POST | `/login` | Customer login |
| GET | `/logout` | End the session |
| GET | `/current-user` | Currently logged-in customer |
| GET | `/{username}` | Customer profile |

**Companies** — `/api/company`, `/api/admin`
| Method | Path | Purpose |
|---|---|---|
| POST | `/api/company/signup` | Register a company (status `Pending`) |
| POST | `/api/company/login` | Company login |
| GET | `/api/company/{username}` | Company profile |
| GET | `/api/admin/companies` | List all companies (admin) |
| PUT | `/api/admin/companies/{id}/status` | Approve or reject a company |
| POST | `/api/admin/login` | Admin login |

**Services** — `/api/services`
| Method | Path | Purpose |
|---|---|---|
| GET | `/all` | All published services |
| POST | `/add` | Publish a service |
| GET | `/company/{username}` | Services of one company |

**Bookings & reviews** — `/api/bookings`
| Method | Path | Purpose |
|---|---|---|
| POST | `/create` | Create a booking |
| GET | `/user/{username}` | A customer's bookings |
| GET | `/company/{companyUsername}` | A company's bookings |
| PUT | `/status/{id}` | Update booking status |
| PUT | `/review/{id}` | Attach a rating and review |
| GET | `/reviews/all` | All reviews |
| GET | `/reviews/full` | Reviews with booking details |
| GET | `/reviews/company/{username}` | Reviews for one company |

```
├── FinalYearProjectApplication.java   # Spring Boot entry point

├── application.properties         # Default config (H2, port 8080, mail placeholders)
├── application-mysql.properties   # MySQL profile
└── static/                        # Front end: HTML pages, styles.css, app.js
```

## Notes and limitations

This is a final-year academic project, and a few things are deliberately kept simple:

- Passwords are stored and compared as plain text — do not reuse real credentials.
- Spring Security permits the application endpoints without authentication; access control is enforced in the front end and service layer, and CSRF is disabled.
- Session state on the front end is kept in `localStorage`.
- The H2 console is enabled by default for convenience; disable it before any public deployment.
